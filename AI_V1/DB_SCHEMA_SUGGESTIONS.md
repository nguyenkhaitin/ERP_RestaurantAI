# Database schema suggestions for KPI/heatmap storage

These are optional tables you can add to persist aggregated KPIs each time `process.py` runs, making dashboard queries fast and stable.

- `daily_kpis` (one row per date):
  - `date` DATE PRIMARY KEY
  - `total_guests` INTEGER
  - `occupancy_rate` INTEGER
  - `avg_dwell_seconds` INTEGER
  - `peak_hour` INTEGER

- `hourly_heatmap` (for heatmap/activity by hour & table):
  - `id` SERIAL PRIMARY KEY
  - `date` DATE
  - `hour` INTEGER (0-23)
  - `table_id` INTEGER
  - `guests` INTEGER
  - `occupied_seconds` INTEGER

- `alerts_log` (store alerts generated by AI):
  - `id` SERIAL PRIMARY KEY
  - `created_at` TIMESTAMP
  - `table_id` INTEGER
  - `alert_type` TEXT
  - `details` JSONB

How to use from `process.py`:
- After computing `table_details` and `dashboard_data`, insert/update `daily_kpis` and append rows into `hourly_heatmap` and `alerts_log`.
